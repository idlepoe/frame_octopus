# Distribution media

These assets demonstrate the actual Frame Octopus Windows app in its English-default Fluent UI theme. The app was run with local Mixkit footage supplied by the developer. No video was uploaded to a service during capture.

## Folders

- `source/`: local copies of the original sample videos, renamed for readable UI labels. This folder is excluded from Git and application packages. The desktop originals are unchanged.
- `screenshots/`: native app-rendered PNGs, including the editor, selected results and zoom preview. `store-*-1920x1080.png` versions fit the full screenshot inside a neutral 1920x1080 canvas without cropping controls.
- `videos/frame-octopus-demo-1080p.mp4`: a 10 FPS automated capture of the real app render tree. It shows upload, original playback, real encoding progress, animated results and zoom preview. Encoding progress is sampled at 2 FPS and replayed at 10 FPS (approximately 5x acceleration); other sections are sampled at 10 FPS. This is not a performance benchmark.
- `outputs/`: example PNG/WebP collections actually generated by the app, not copies of the source video.
- `verification.json`: measured output sizes/settings and capture frame count, without machine-specific paths.
- `quality-comparison/`: the same source encoded at 1 MB and 20 MB, with measured resolution, FPS and encoder quality.

Rebuild the Windows release, then run `tool/capture_distribution_media.ps1` from the project root. The app remains open after capture. Frame scratch files and full internal reports remain under the Git-ignored verification directory.

The demo and `quality-comparison/` capture the preceding precision-search revision. `speed-comparison/` contains the current faster optimizer results and report. Its 20 MB output retains the same resolution/FPS with Q97 instead of Q97.9.

## Predictive optimizer revision

Current measured examples and sanitized report are in `predictive-optimization/`. They use up to 12 representative frames for size estimation and only encode complete animations for final output/correction. Earlier screenshots/demo and comparison folders are historical captures of prior revisions. The predictive comparison retains the same scenes/FPS and a strict measured byte limit; see docs/TESTING.md for local elapsed-time and quality tradeoffs.

## Current fast policy

The latest single-sample results are in `fast-optimization/`. One representative Q90 sample selects the output; spare capacity may allow Q95 without another sample. Unused bytes are accepted and only actual overflow causes correction. This deliberately trades fine capacity utilization for faster generation, particularly at tight limits. Previous folders document earlier revisions.

## Automatic FPS verification

`automatic-fps/` contains output from a locally generated 60 FPS test pattern and a sanitized native report demonstrating automatic 30 FPS output. Automatic FPS also reduces the rate for long clips to approximately 120 frames per scene, without adding compression probes.
